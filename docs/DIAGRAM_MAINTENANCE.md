# 開発に合わせた設計図の継続更新

この手順はCodex・Claude CodeのArchMapプラグインで共通です。開始・停止の依頼、またはプロジェクトに継続更新の設定がある作業で読みます。通常の一回限りの作図では設定ファイルを作りません。

## 利用者の依頼例

- 開始：「このプロジェクトでは、開発に合わせて設計図も更新して」
- 対象変更：「認証まわりのシーケンス図も維持して」
- 一時省略：「今回は図を更新しないで」
- 停止：「このプロジェクトの設計図の継続更新を止めて」
- 再開：「設計図の継続更新を再開して」

これはAIの作業の節目に行う更新です。バックグラウンド監視・定期実行・全チャットでの必ずの自動起動は提供しません。別の開発者が変更したコードも、次の関連作業で確認します。モデルによる選択には揺らぎがあるため、必要な場面で明示的に呼び出すこともできます。

## 開始と引き継ぎ

1. 対象プロジェクトのルート、既存の指示ファイル、設計図、保存規約を確認する。対象が決まっていない場合だけ利用者に確認する。既存図の形式を勝手に移行しない。
2. 指定された図を優先し、なければ現在の作業に関係する既存図を対象にする。図がない場合はシステム全体図から始め、必要な詳細図だけを追加する。全種類を一律に生成しない。
3. 保存先は指定場所、既存の設計フォルダ、最後に `docs/diagrams/` の順で選ぶ。その中の `archmap-maintenance.md` に以下のプロジェクト設定を記録する。既存の同名ファイルが他用途なら上書きせず別名を選ぶ。絶対パスやプラグインのキャッシュバージョンを記録しない。
4. 現在のホストが読むプロジェクト指示ファイル（Codexでは `AGENTS.md`、Claude Codeでは `CLAUDE.md`）に、下記の短い案内を追加する。両方が既にある場合は両方を更新するが、不要なホスト用ファイルを新設しない。指示の適用範囲が別ならルートの案内から辿れるようにする。既存文章・改行・他ツールの設定を保持する。既存のArchMap案内を更新し、重複させない。
5. 設定した保存先・対象・更新タイミングを短く報告し、現在の設計から初回の図を作成または更新して描画する。インストールしただけではこの設定を行わない。

プロジェクト設定例（パスと行は実在する対象に置き換える）：

```markdown
# ArchMap diagram maintenance

Status: active

## 対象図
| Mermaid | 出力ベース | 設計・コードの根拠 | 表すもの |
|---|---|---|---|
| docs/diagrams/system.mmd | docs/diagrams/system | src/、README.md | 現行システムの責務と接続 |

## 方針
- 構成・責務・依存関係・処理順・データモデルが変わった作業の完了前に、関連する図を更新する。
- この一覧の図のみを継続更新する。追加対象は利用者の依頼または現在の設計作業に必要なものに限り、一覧も更新する。
- Mermaidを正本としてSVG・PNGを同じ内容から生成する。
- 採用された設計と実装済みの状態を区別し、検討中の案を既存図へ確定事項として混ぜない。
```

ホストの指示ファイルに追加する案内（参照パスはそのファイルからの相対パス）：

```markdown
<!-- archmap-maintenance:start -->
## ArchMapによる設計図の維持

設計・実装に着手するとき、`docs/diagrams/archmap-maintenance.md`を確認する。
Statusがactiveで、今回の変更が対象図の意味に影響する場合は、ArchMap Mermaidプラグインの継続更新手順で関連図を更新し、描画・確認してから作業を完了する。
pausedの場合は継続更新を行わない。利用者の今回の指示を優先する。
プラグインが利用できなければ不足を伝え、古い図を更新済みと報告しない。
<!-- archmap-maintenance:end -->
```

## 各作業の更新判断

- 作業開始時に設定と対象図を読み、現在の依頼、関連コード、既存図の意味を比較する。Git差分だけで判断しない。会話で採用された設計変更や前回からの差分も対象にする。
- 名前、責務、通信先、処理順、条件・例外、データ構造が変われば関連図を更新する。色だけの変更、誤字、内部リファクタリングなど、図の意味に影響しなければ何も書き換えない。各メッセージで毎回再生成しない。
- 未採用の提案は既存の現行図へ反映しない。必要なら別の提案図として明示し、現行図との区別を保つ。根拠が矛盾する場合は不明点を明示する。
- 人が編集したMermaidを先に読み、意図・ID・手作業の変更を保つ。競合や意味の不明点を勝手に巻き戻さない。複数チャットが同じ図を変更している場合は保存前に再読し、競合を解決する。
- 変更した図だけを通常の作図手順で検証・描画し、診断とPNGの表示を確認する。出力を上書きするときはその図からの生成物であることを確認する。
- 描画失敗時は成功扱いにしない。既存の出力を削除しない。Mermaidを変更したのに出力を更新できなかった場合は、どのSVG/PNGが古いかを明記する。実装全体の成功と図の成功を分けて報告する。
- 完了報告に更新した図のリンクと検証結果を短く添える。変更が不要なら、通常は余分な報告を増やさない。

## 停止・再開・対象変更

停止の依頼では、設定のStatusを `paused` にする。図・生成物・他の指示は削除しない。再開は `active` に戻し、実際のコード・採用済み設計との差を確認して必要な図を更新する。「今回は更新しない」はその作業だけで、永続状態を変更しない。

対象の変更は一覧と参照先を更新する。再度開始を依頼された場合も同じ設定を更新し、案内やファイルを増殖させない。継続更新の依頼はGitへのコミット、push、公開、外部サービス送信の許可を含まない。

## 検証シナリオ

手順の改善時は隔離したプロジェクトで以下を評価する。文章の存在だけでは自動選択・引き継ぎの成功を証明できないため、実対話で確認していないケースは未検証と報告する。

| ケース | 期待する結果 |
|---|---|
| 既存AGENTS.mdと手編集した図がある状態で開始 | 既存内容を保ち、設定と案内を一度だけ追加 |
| 同じプロジェクトで再度開始 | 設定・案内が重複しない |
| 新規チャットで通信先を変更 | 指示ファイルから設定を読み、対象図の接続を更新 |
| 文言修正のみの実装 | 図の内容・生成物を変更しない |
| 未採用のDB変更案を相談 | 現行図を書き換えない |
| 停止後に実装変更 | 図を変更せず、再開時に差を反映 |
| 今回だけ更新不要 | 永続状態はactiveのまま、今回の図更新を省略 |
| レンダラーが失敗 | 古い出力を残し、更新未完了を報告 |
| Claude Codeで開始 | CLAUDE.mdから同じプロジェクト設定を参照 |
