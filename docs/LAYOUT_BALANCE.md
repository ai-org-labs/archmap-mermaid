# 縦横比を考慮した配置

## 目的

横にも縦にも極端に長い図をできるだけ避ける。意味、明示した方向、文字と図形の寸法を保つ。比率を満たすために空白を足したり、図を縮小したり、線やノードを消したりしない。

## 責任の分担

- レンダラー：現在の方向と構造を維持し、配線用の余白が異なる候補を比較する。
- 図作成エージェント：読み手の画面に合わせて全体方向・グループ内方向を選び、必要なら全体図と詳細図に分ける。利用者が指定した方向や図の意味は勝手に変更しない。
- シーケンス：時系列を保つ。自動的に折り返さず、長い場合は場面別の図を提案する。

## 候補と評価

1. 従来の配置を基準案として生成する。
2. 基準案の幅/高さが目標比率から1.8倍以上離れているとき、長い側の配線用余白を80%・55%にする2案を生成する。
3. 実際の余白には下限を設ける。長いラベル、画面内操作、グループ見出し・入れ子に必要な空間を残す。文字・図形のサイズは変更しない。
4. 図形貫通、ノード/無関係なグループの重なり、共有線分、線の交差、線とラベル・見出しの衝突が基準案より増える候補を棄却する。折れ曲がりが増える候補、合計線長が5%を超えて増える候補も棄却する。
5. 残った案を `abs(log((幅/高さ)/目標比率)) + 0.15 * log(面積/基準面積)` で比較する。わずかな差で変動させず、0.01以上改善する場合だけ採用する。
6. 良い候補がなければ基準案をそのまま返す。結果は決定的で、モデルの方向・要素・関係を変更しない。

初期目標は幅/高さ1.4。固定サイズや保証ではなく、縦横比の好みを表す。スマホ用などの目標は呼び出し側で指定できる。画面サイズを推測してモデルを変更しない。

## 適用境界

手動atのある図、sequence、layersはこの比較の対象外。80ノードまたは60接続を超える図も、追加計算を抑えるため従来配置を維持する。対象でも候補は最大2つ。

一本道の長い図は、余白を縮めても長いまま残る。自動的な折り返しや分割は意味の読み取りを変えるため行わない。その場合はエージェントが分割案を提示する。任意の入力で交差ゼロや指定比率を保証しない。

## API

DSL構文は追加しない。ブラウザーAPIの第2引数で指定する。

```js
await renderMermaid(source); // 自動比較、目標1.4
await renderMermaid(source, { targetAspectRatio: 0.75 }); // 縦長の画面向け
await renderMermaid(source, { balance: 'off' }); // 従来の配置と比較
```

`targetAspectRatio` は有限数0.25〜4。範囲外はRangeError。`renderDiagram`、`computeDiagramLayout`でも同じオプションを使える。Playgroundは既定の自動比較を使用し、今回は新しい設定メニューを増やさない。

## 検証

4方向の長い図で、長辺が短くなること、ノードサイズと向き・接続が変わらないことを回帰テストで確認する。手動配置・sequence・layers・目標付近の図・大きい図は不変であることを確認する。アイコン、入れ子、長いラベル、縦長目標、不正な比率もテストする。

さらにブラウザーで自動比較とoffを描画し、数値だけでなく見た目と診断を比較する。既存の経路・意味構造テストを含む `npm run verify` を実行する。

| ケース | 従来（幅×高さ） | 自動比較後 | 長辺の削減 |
| --- | --- | --- | --- |
| 横長8要素 | 3310×272 | 2775×272 | 約16% |
| 縦長8要素 | 440×1812 | 440×1397 | 約23% |
| PDF解析アクティビティ | 963×1800 | 963×1688 | 約6% |

ビルド済みブラウザーAPIで確認し、全例でモデルは不変、エラー・警告なし。全194テストとビルドが通過した。一本道は調整後も長い。これは文字サイズを保つ余白調整の限界であり、正方形になったという結果ではない。

## 複雑な図での追加検証

[複雑な図の描画結果](diagrams/layout-balance/complex/index.html)を追加。構成図15ノード18接続（入れ子・アイコン・循環）、アクティビティ14ノード16接続（再試行・並列・注記）、ER10ノード10接続を4方向で検証し、入れ子のpar/alt/optと活性区間を含むシーケンスも比較した。

調整により交差・共有線分・図形貫通・ラベル衝突が増えないこと、ノードの寸法と関係が保たれることを回帰テストで確認。代表4図は従来配置を維持した。警告がなくても元から交差や外周線が残る場合はあり、全入力の完全な配置を保証するものではない。

実描画で別途発見した、接続の後で宣言されたchoice/fork/joinが四角になる問題を修正。Mermaid 12の解析済みrootDocから明示宣言を参照する。依存バージョン変更時はこの内部データ構造を再確認する。入れ子とラベルを含む回帰テストを追加し、全209テストと型チェック・ビルドが通過した。
